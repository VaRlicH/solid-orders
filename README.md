# Управление заказами: SOLID на Go

Рефакторинг учебного сервиса: сохранение заказа и уведомление клиента разделены.

## Запуск

Нужны Go 1.22 или новее и C-компилятор (GCC в PATH), поскольку драйвер `github.com/mattn/go-sqlite3` использует CGO.

В PowerShell из папки проекта:

```powershell
$env:CGO_ENABLED = '1'
go mod download
go run .
go test ./...
```

Демонстрация создаёт два заказа в `orders.db`: с EmailSender и SMSSender. Третий заказ сохраняется в памяти и использует EmailSender. Повторный запуск добавляет новые заказы. Данные в памяти исчезают после завершения программы.

Email и SMS — имитации отправки в консоли, как в исходном задании; реальные сообщения не отправляются. `customer` остаётся именем клиента. Для настоящей отправки понадобятся контактные данные и интеграция с провайдером.

## Принципы SOLID

| Принцип | Реализация |
| --- | --- |
| SRP | OrderService управляет созданием заказа; SQLiteRepository и MemoryRepository сохраняют данные; EmailSender и SMSSender уведомляют клиента. |
| OCP | Новая БД реализует RepositoryWriter, новый канал — Notifier; код OrderService не меняется. |
| LSP | EmailSender и SMSSender имеют одинаковый контракт Send(customer string) error и взаимозаменяемы в сервисе. |
| ISP | RepositoryInitializer содержит только Init, RepositoryWriter — только Save. Хранилищу в памяти не нужен метод создания таблиц. |
| DIP | OrderService получает RepositoryWriter и Notifier через конструктор; конкретные реализации выбираются в main. |

## Файлы

- `order.go`: модель, интерфейсы и бизнес-логика.
- `repository.go`: SQLite и память.
- `notifier.go`: Email и SMS.
- `main.go`: подключение БД, подготовка таблицы и внедрение зависимостей.
- `order_test.go`: успешное создание, ошибки сохранения и уведомления, интеграционная проверка SQLite и замена отправителей.

При ошибке сохранения уведомление не отправляется. При ошибке уведомления заказ уже сохранён: сервис возвращает ошибку с этим уточнением и сохраняет исходную причину через `%w`. Автоматический повтор создания может создать дубликат. Транзакционный outbox и повторная доставка выходят за рамки задания.

Для минимального изменения исходной модели оставлены `float64` для суммы и строка для продуктов. В промышленной системе деньги лучше хранить целым числом минимальных денежных единиц, а позиции заказа — структурированно.
